# gemini_budget

[English](README.md) | **Русский**

Общий учёт квот Gemini API для всех проектов текущего пользователя. Несколько
приложений с одними и теми же ключами видят одни счётчики и вместе не выходят за
бесплатный тариф. Без зависимостей: не нужны ни Google SDK, ни Flask, ни что-то ещё.

## Установка

```bat
pip install git+https://github.com/biolog-end/gemini-budget.git
```

Для разработки — редактируемая копия:

```bat
pip install -e путь\к\gemini-budget
```

Состояние хранится в `~/.gemini_budget/state.json` (`%USERPROFILE%\.gemini_budget` в
Windows). Переменная `GEMINI_BUDGET_DIR` переносит его сразу для всех проектов. У
каждого виртуального окружения своя установка пакета, но файл состояния общий. Для
изолированных тестов функции принимают `state_file=...`.

## Модели и лимиты

```python
import gemini_budget as gb

models = gb.free_models()                         # модели переписки с бесплатной квотой: id, label, task, limits
voices = gb.free_models(task='tts')               # модели озвучки
speech = gb.free_models(task='transcription')     # модели транскрипции
catalog = gb.models()                             # весь профиль, включая нулевые квоты
default = gb.limits('gemini-3.8-flash')           # rpm, tpm, rpd
configured = gb.limits('gemini-3.8-flash', key)   # с ручными правками этого ключа
rows = gb.status(key)                             # все остатки этого ключа
row = gb.status(key, 'gemini-3.8-flash')          # одна модель
```

Встроенный профиль — снимок бесплатных квот одного проекта AI Studio на 18.09.2026. Это
не обещание Google для любого аккаунта: если у вашего проекта другие лимиты, поправьте
их через `correct()`.

| Модели | Бесплатная квота |
| --- | --- |
| 2.5 Flash, 2.5 Flash Lite, 3 Flash, 3.5 Flash, 3.6 Flash, 3.7 Flash, 3.8 Flash | 20 запросов в день |
| 3.5 Flash Lite, 3.1 Flash Lite | 500 запросов в день |
| Gemma 4 26B, Gemma 4 31B | 30 RPM, 16 000 TPM, 14 400 запросов в день |
| 2.5 Pro, 3.1 Pro, 2.5 Pro TTS | нет |

У моделей переписки Gemini 250 000 входных TPM. Отдельные профили описывают озвучку и
транскрипцию — это не модели для переписки. Все функции возвращают копии.

## Учёт запроса

```python
model = 'gemini-3.8-flash'
reservation, reason = gb.reserve(key, model, input_tokens=estimated_input)
if reservation is None:
    raise RuntimeError(reason)                    # перейти к следующему ключу или модели
try:
    response = client.models.generate_content(model=model, contents=contents)
except Exception:
    gb.finish(key, model, reservation, success=False)
    raise
else:
    usage = response.usage_metadata
    gb.finish(key, model, reservation, success=True,
              input_tokens=getattr(usage, 'prompt_token_count', None))
```

- `reserve()` занимает запрос и оценку входных токенов до HTTP-вызова. Резервы
  учитываются в остатке, поэтому два проекта не займут последний запрос одновременно.
  Они показываются отдельно: `reserved_day`, `reserved_minute`, `reserved_tokens_minute`.
- В расход попадают только успешные ответы (`success=True`); пригоден ли ответ, решает
  вызывающий проект. Ошибка или пустой ответ (`success=False`) освобождают резерв и не
  меняют RPM, TPM и RPD. Минутное окно успеха начинается с получения ответа.
- После ошибки API можно передать
  `failure={"kind": "quota", "until": unix_time, "reason": "..."}`, чтобы поставить
  модель на паузу для этого ключа. Подробный `report` поддерживает `scope` и `zero_limit`.
  В `reason` не должно быть секретов. Неизвестная ошибка сама по себе паузу не ставит.
- Один вызов `finish()` на резерв; повторный вызов не засчитывает успех дважды.
- RPM и TPM считаются в скользящем окне 60 секунд. RPD сбрасывается в полночь по
  тихоокеанскому времени с учётом перехода на летнее время.

У одного ключа один и тот же SHA-256-отпечаток во всех проектах, сами ключи не
сохраняются. Атомарная запись и блокировки ОС защищают состояние от одновременной
работы процессов в Windows, Linux и macOS; во время сетевого запроса блокировка не
держится.

Учитываются только проекты, которые вызывают `reserve()` и `finish()`. Локальный учёт
не обязан совпадать с Google: сервер может считать иначе или видеть другие приложения с
этим ключом. Оценка токенов до запроса приблизительная и задаётся вызывающим проектом.

## Ручная правка

```python
gb.correct(key, model, {
    'rpm': 5, 'tpm': 250000, 'rpd': 20,
    'requests_today': 3,
    'requests_last_minute': 1, 'input_tokens_last_minute': 1200,
})
```

Правка действует для всех проектов с этим ключом. Текущие резервы сохраняются, старая
пауза API снимается. Нулевой лимит выключает модель на этом ключе до новой правки.
Правка локального состояния не меняет реальную квоту Google.

`requests_today` и `successful_today` — один счётчик успешных ответов; `correct()` для
совместимости принимает и `successful_today`, но значение задаётся через
`requests_today`. У строк старого формата v1 сохраняются записанные успехи, а старые
минутные попытки без признака успеха отбрасываются; текущие резервы остаются.

## Перенос старого журнала

`gb.import_legacy(path)` один раз для каждого исходного файла переносит старый журнал
проекта в общее состояние. Дневные значения объединяются по максимуму, совпадающие
минутные резервы не дублируются, поэтому повторный импорт копии того же проекта не
удвоит историю. Старый файл не удаляется. Перед переносом перезапустите проекты: уже
запущенные процессы продолжают писать в старый журнал.

## Командная строка

```bat
gemini-budget models                 :: бесплатные модели переписки (--task tts | transcription)
gemini-budget status                 :: остатки для GEMINI_API_KEY или GOOGLE_API_KEY
gemini-budget path                   :: где лежит файл состояния
```
